First approved request

The server verifies publication, Guardian approval, balance, and access history. One active access record is created and the Coin transaction proceeds.

One user · one item · one active row

Simultaneous duplicate request

The database uniqueness guard rejects the duplicate insert. The server re-reads the winning access record and returns it idempotently instead of creating a second active row.

Concurrent request → existing access

Historical states remain visible: revoked and expired records are preserved for the access history; only duplicate active state is blocked.
